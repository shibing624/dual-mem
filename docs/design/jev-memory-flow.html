01 / 四层按处理阶段，kind 按内容语义

L0_RAW

原始证据

输入原文、角色、来源、语义时间。

先落盘；模型失败也保留。默认问答不混入 raw。
L1_FACT

显式事实与事件

事实、金额、发生过的独立事件、明确计划。

kind = fact / intention。重复文本不等于同一事件。
L2_PROFILE

身份、画像与状态

当前所在地、职业、偏好、身份维度。

JEV 选择 representation；每个维度独立演化。
L3_DERIVED

跨证据推导

模式、摘要、带证据的推导意图。

仅 dual digest 生成；kind 区分 schema / summary / intention。

旧七层名只作读兼容别名，枚举迭代与新写入只使用四层。层的多少不承担「是否值得记住」的判断。

02 / System1：统一快写与关系决策

STEP 1
保留 L0 原文去宿主注入块；原始来源独立 ID。
→
STEP 2 / GENERATE
只生成候选明确事实、原子维度、日期、否定与来源。
→
STEP 3 / JEV
批量覆盖 + 动作 + 目标 + 表示同一 state：incoming source + current + history_versions。
→
STEP 4 / STORE
追加并链接验证 scope / revision / epoch；journal → append → link。
system1：写 L0/L1/L2，版本决策完成后返回，不运行跨证据认知。

调用次数

正常：一次生成 + 一次 JEV。所有候选的独立问题合并提交，复用同一个 HTTP 客户端。

多目标才增加筛选问题；MERGE 才增加合并文本生成和 JEV 无损检查；大材料先用 JEV 分页选择相关上下文。

执行约束与语义判断分离

JEV 判断持久价值、来源支持、更新类型与目标。代码只检查合法 ID、scope、重复消费、先后依赖、有效期格式及预算。

INVALID / NEED_CONTEXT 或不一致动作保留原文并报错，不静默改成 SUPPLEMENT。问题彼此独立，不能读别的问题答案。

03 / 已知与更新：从当前头判断，不从相似度判断

旧 novelty 门：嵌入距离低 → 跳过写入

更新经常和旧事实非常接近。用二值 novelty 把「已知」和「更新」混在一起，会直接丢弃状态变化。

weak_candidate_score：旧路由，与写入信用不同

原本仅用于决定是否跑策略。新设计删除相似度路由：候选都交给 JEV。embedding 保留给索引和读侧检索。

04 / 动作与六种 update_type

动作 / 关系适用语义旧版本新版本与读取
ADD / OVERRIDE同主体、同维度当前状态变化保留，is_latest=falsesupersedes 当前头；默认读新值
ADD / MERGE同一对象的互补片段；数字、事件、其他维度不能丢保留，is_latest=false生成合并文本，JEV 校验无损；合并来源时间
ADD / SUPPLEMENT独立兼容事实或另一次事件保持 latest新增事实；不错误消费旧目标
ADD / TEMPORAL限时情况，不覆盖长期基线保持 latest保存 valid_from / valid_until / temporal_scope
ADD / NEGATE明确否定或终止已有主张保留，is_latest=false否定版本成为当前；不回填肯定旧事实
ADD / CONFLICT来源冲突且无足够依据选真值保持 latest两侧并存，conflicts_with 显式标注
SKIP当前有效事实完全覆盖候选不改不创建重复结构化事实；L0 原文仍保留
DELETE撤回当前表示或重复表示归档保留，is_latest=false只归档；物理清除 scope 是独立 delete_bulk API
RAW_ONLY没有持久事实或计划不改只保留来源；和「当前已知」分开记录

05 / Dual：在明确的 digest 点做跨证据认知

QUEUE
捕获任务水位同 scope 聚合 task IDs，新到达任务留给下一轮。
→
MATERIALS
真实事实分页latest L1/L2；按 fact 数和字符预算，孤立点也处理。
→
GENERATE + JEV
推导与覆盖校验memories + evidence_ids + processed_ids；检查引用与支持。
→
COMMIT
版本化 L3同一追加协议；证据覆盖与版本一起持久化。

大 cluster 不直接截断后标完成

本管线不使用聚类阈值或高相似去重来丢弃证据。默认每页 ≤120 facts，并受生成与 JEV 预算双重约束。

超预算或未覆盖 input IDs：保留 pending；失败 scope 独立重试，已成功 scope 可确认。

来源变化，推导也过期

事实退休时，引用该证据的旧 L3 推导设为非 latest，历史保留；剩余支持证据恢复 fresh，下一次 digest 重建。

Kuzu 是证据关系投影；VDB 管当前版本。图失败可以重建，不能把旧图事实当当前。

示意流程，不是吞吐 benchmark。默认 reconcile_concurrency=4；JEV 所有批次和所有调用共享 semaphore。

CAS 检查的是两个层级

target revision 阻止消费过时旧版本；scope epoch 阻止两个“没看到现有事实”的新增决策同时生效。

竞争失败重新交给 JEV；最后一次 scope 锁内重试避免同用户重试风暴。不同用户不阻塞。

Journal → 追加 → 链接 → 投影确认

完整计划先持久化。进程中断后，下一次存储操作先恢复；图投影失败由下次 digest 补回。重放验证不可变语义指纹；审计事件按 event_key 去重。

非法向量在日志前拒绝。本机进程文件锁；不是跨机器分布式事务。request_id 支持同输入重试。

Venus / 2026-10-15

真实 JEV：北京→上海→回北京→重复当前，分别 SUPPLEMENT / OVERRIDE / OVERRIDE / SKIP。

单次公共入口约 408–562 ms；四个独立 scope 并发总耗时约 632 ms。

生成与向量用确定性适配器；验证 JEV 与 SDK 版本行为。最终 hy3 + JEV 四步约 6.8–15.4 秒，核心状态与 SKIP 断言通过；一次 JEV/步。独立搬家事件仍出现不当 OVERRIDE，关系质量待评测。重复运行也暴露抽取遗漏。向量仍为确定性适配器。

源码对应位置与待评测能力

providers/jev.py：API、拆包与全局并发；agent/reconciler.py：动作 / 目标 / history_versions；agent/mem_agent.py：候选、版本计划、并发重决策；storage/vector_store.py：CAS、journal、迁移、证据失效；system2/system2_agent.py：材料分页和真实覆盖；system2/system2_writer.py：显式 digest 与任务水位。

仍需业务数据 A/B 和真实向量模型联调：中文语义准确率、六类更新分布、MERGE 无损性、多源冲突、超大 scope 的材料调用成本。预算不足与不一致决策会显式失败并保留来源。
